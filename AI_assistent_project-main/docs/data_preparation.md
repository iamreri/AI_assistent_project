# Подготовка данных для RAG-ассистента

## 1. Источники
В качестве базы знаний использовались официальные локальные нормативные акты (ЛНА) МГТУ им. Г.И. Носова, регламентирующие учебный процесс студентов (Положение о промежуточной аттестации, о стипендиях, о переводе и отчислении, правила проживания в общежитии, Устав и др.). 
Всего обработано 9 PDF-документов (один файл оказался сканом), общим объемом более 300 чанков. Документы скачаны с официального сайта (`magtu.ru/sveden/document.html`).

## 2. Очистка и дедупликация
Текст извлекался с помощью PyMuPDF. Были удалены номера страниц, технический мусор, исправлены переносы слов. Дедупликация проводилась по хэшу нормализованного текста (дубликатов не обнаружено).

## 3. Стратегии чанкинга и эксперимент
Были протестированы два варианта разбиения:
1. `fixed` (фиксированный размер ~500 токенов с перекрытием) — 341 чанк.
2. `semantic` (по смысловым блокам/абзацам с сохранением заголовков) — 392 чанка.

Для оценки качества был сформирован мини-бенчмарк из 10 студенческих вопросов (файл `data/questions.csv`) с ключевыми словами. Оценка проводилась по метрике `recall@5` (попадание нужного фрагмента в топ-5).

**Результаты эксперимента:**
* `chunks_fixed`: recall@5 = 80%
* `chunks_semantic`: recall@5 = 80%

**Принятое решение:** Выбран вариант **`semantic`**. Несмотря на одинаковую метрику, данный метод разбивает текст по смысловым границам и сохраняет заголовки разделов (например, шапку документа), что обеспечит более качественную генерацию ответов в RAG-системе.

## 4. Метаданные
Каждый чанк содержит метаданные: `document_id`, `document_title`, `source`, `date`, `document_type`, `department`, `page`, `chunk_id`, `text`.
