# RAG-компонент ассистента

## 1. Архитектура и Baseline
В основе системы лежит классический пайплайн RAG (Retrieval-Augmented Generation):
1. **Вопрос пользователя** → 2. **Embedding (модель e5-small)** → 3. **Vector Search (ChromaDB)** → 4. **Top-K фрагментов** → 5. **LLM (GigaChat)** → 6. **Ответ + источники**.

В качестве базовой (baseline) версии был реализован простой поиск по 4 фрагментам (`top_k=4`) с использованием семантического чанкинга и модели эмбеддингов `intfloat/multilingual-e5-small`.

## 2. Проведенные эксперименты

В ходе работы было проведено три обязательных эксперимента. Подробные протоколы находятся в папке `experiments/`.

1. **Размер chunk (Эксперимент 1):** Проверены размеры 300, 500 и 800 символов. Выяснилось, что куски по 300 символов разрушают логику документов, и модель выдает случайные факты. Оптимальным выбран размер **800 символов** (или семантический чанкинг, который сохраняет структуру списков).
2. **Количество фрагментов top_k (Эксперимент 2):** Проверены значения 2, 4 и 8. Значение `top_k=2` дает слишком короткий ответ, а `top_k=8` может перегрузить модель. Оптимальным выбрано **top_k=4**. *(Также в ходе тестов был выявлен баг GigaChat: при определенных словах модель блокирует генерацию, но смена вопроса на нейтральный решила проблему).*
3. **Модели эмбеддингов (Эксперимент 3):** Сравнили `intfloat/multilingual-e5-small` и `paraphrase-multilingual-MiniLM-L12-v2`. Вторая модель показала неудовлетворительный результат (потеряла смысл контекста), поэтому в итоговой системе закреплена **e5-small**.

## 3. Ответ на контрольный вопрос
**«Стало ли наше усложнение (RAG) действительно лучше обычного поиска по сайту?»**

**Да, однозначно.**
Обычный поиск (например, встроенный поиск на сайте WordPress) работает по ключевым словам (TF-IDF/BM25). Если студент введет: *«Что будет, если я завалю сессию?»*, обычный поиск не найдет ничего, потому что в документах нет слова «завалю», там написано «ликвидация академической задолженности».

RAG-система использует **векторный поиск (эмбеддинги)**. Она понимает *смысл* вопроса. Модель `e5-small` переводит «завалю сессию» в вектор, который математически близок к вектору текста про «академическую задолженность».
Кроме того, LLM (GigaChat) не просто выдает список ссылок (как поисковик), а **читает** найденные куски и формулирует понятный, человеческий ответ, оставляя ссылки на источник. Это избавляет студента от необходимости читать 20 страниц юридического PDF ради одного абзаца.
