# Требования к системе

## 1. Функциональные требования

### 1.1. Работа с пользовательским запросом

**FR-01. Приём запроса**
Система должна обеспечивать ввод пользователем запроса на естественном языке.

**FR-02. Анализ запроса**
Система должна анализировать содержание пользовательского запроса для определения необходимой пользователю информации.

**FR-03. Обработка различных формулировок**
Система должна обрабатывать различные формулировки запросов, имеющие одинаковый или близкий смысл.

### 1.2. Поиск информации

**FR-04. Поиск в базе знаний**
Система должна выполнять поиск информации в подготовленной базе знаний, содержащей университетские документы и учебно-методические материалы.

**FR-05. Поиск по фрагментам документов**
Система должна находить отдельные фрагменты документов, релевантные пользовательскому запросу, а не только документы целиком.

**FR-06. Использование нескольких документов**
Система должна обеспечивать использование информации из нескольких релевантных документов при формировании ответа.

### 1.3. Формирование ответа

**FR-07. Формирование ответа**
Система должна формировать ответ на естественном языке на основе найденных релевантных фрагментов документов.

**FR-08. Обобщение информации**
Система должна обеспечивать обобщение информации из нескольких найденных фрагментов при необходимости формирования единого ответа.

**FR-09. Соответствие ответа источникам**
Содержание ответа должно соответствовать информации, содержащейся в найденных документах.

**FR-10. Отсутствие неподтверждённой информации**
Система не должна формировать фактические утверждения о деятельности университета, которые не подтверждаются информацией из базы знаний.

### 1.4. Работа с источниками

**FR-11. Указание источников**
Система должна указывать документы, использованные при формировании ответа.

**FR-12. Идентификация источника**
Пользователь должен иметь возможность определить, на основании какого документа или документов сформирован ответ.

**FR-13. Дополнительная информация об источнике**
При наличии соответствующих метаданных система должна отображать дополнительную информацию о найденном фрагменте, например номер страницы документа.

### 1.5. Обработка недостаточной информации

**FR-14. Отсутствие информации**
Если в базе знаний отсутствует информация, необходимая для ответа на запрос, система должна сообщить пользователю об отсутствии соответствующих данных.

**FR-15. Запрет на выдумывание ответа**
При отсутствии достаточной информации в базе знаний система не должна заменять отсутствующую информацию предположениями или собственными знаниями языковой модели.

**FR-16. Обработка неоднозначного запроса**
При невозможности однозначно определить содержание запроса система должна запросить у пользователя уточнение либо предоставить ответ только в части, которая подтверждается найденными источниками.

**FR-17. Обработка противоречивой информации**
Если в найденных документах содержится противоречивая информация, система должна сообщить пользователю о наличии противоречия и указать соответствующие источники.

## 2. Нефункциональные требования

**NFR-01. Естественное взаимодействие**
Система должна обеспечивать взаимодействие с пользователем на естественном языке без необходимости использования специальных поисковых операторов.

**NFR-02. Понятность ответа**
Ответ системы должен быть сформулирован в понятной для студента форме.

**NFR-03. Проверяемость информации**
Ответ системы должен сопровождаться информацией об использованных источниках, позволяющей пользователю самостоятельно проверить полученную информацию.

## 3. Ограничения

**C-01. Ограниченный состав базы знаний**
В рамках прототипа используется ограниченный набор заранее выбранных университетских документов и учебно-методических материалов.

**C-02. Отсутствие персональных данных**
В базе знаний прототипа не должны использоваться персональные данные студентов.

**C-03. Отсутствие доступа к личному кабинету**
Система не должна получать информацию из личного кабинета студента.

**C-04. Отсутствие персонализированной учебной информации**
В рамках прототипа не предусматривается получение и отображение индивидуальных оценок, задолженностей, персонального расписания и других персонализированных учебных данных.

**C-05. Отсутствие административных действий**
Система не должна изменять данные в информационных системах университета и выполнять административные действия от имени пользователя.

**C-06. Ограничение источников информации**
Ответы системы должны формироваться на основе информации, содержащейся в подготовленной базе знаний. Языковая модель не должна рассматриваться как самостоятельный источник официальной информации университета.

**C-07. Отсутствие обязательных платных сервисов**
Реализация прототипа не должна требовать обязательного использования платных API или иных платных внешних сервисов.

**C-08. Ограничение вычислительных ресурсов**
Выбранные программные компоненты должны соответствовать доступным вычислительным ресурсам проекта. Наличие выделенного графического процессора не является обязательным требованием.

**C-09. Контроль результатов**
Корректность ответов системы должна проверяться на этапе тестирования путем сопоставления сформированных ответов с содержанием исходных документов.
